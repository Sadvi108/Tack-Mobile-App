# Tack 0.2.1 — a fresh single-APK build

Same app as 0.2.0. Rebuilt from a clean release build and published as one
universal APK, after 0.2.0 downloaded but would not install on a test phone.

Android version name is `0.2.1`; version code is **7000**. That clears every
code this app has ever shipped — `1` and `2001` from v0.1.0, and `4000`,
`5000` and `6000` from the v0.2.0 split APKs — so no phone can see this as a
downgrade whichever build it already has.

## One file

`Tack-0.2.1-universal.apk` works on any Android phone from 7.0 onward. It
carries `arm64-v8a`, `armeabi-v7a` and `x86_64` together, which is why it is
about 69 MB: three architectures in one file, so nobody has to know which one
their phone needs.

## If 0.2.0 would not install

The build was not the problem — 0.2.0's APK verified intact and its providers
were correctly namespaced. The usual cause of "App not installed" is a copy of
Tack already on the phone that was **signed with a different key**, which
Android refuses to replace. A development build installed over USB is signed
with the Android debug key, not the release key, and will block every release
build from installing.

If this build still will not install:

1. Uninstall Tack completely — long-press the icon, App info, Uninstall.
2. Install `Tack-0.2.1-universal.apk` again.

Nothing is lost. Profiles, roadmaps, skills and documents live in the database,
so signing back in restores them. Only the offline queue and the light/dark
preference are on the phone.

If Play Protect shows "Unsafe app blocked", the "Install anyway" is behind
**More details**. Android needs roughly 200 MB free to install a 69 MB APK.

## Signing

## Validation

Flutter analysis clean; 366 Flutter tests pass. The APK was verified after
building: package `com.tack.tack`, version code 7000, minSdk 24, all three
ABIs, signature intact.
